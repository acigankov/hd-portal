# Регистрация заявок из почты

Портал принимает письма с нескольких почтовых ящиков и заводит по ним заявки,
а публичные ответы специалистов уходят автору письма с того же адреса, на который
обращение пришло изначально.

## Как это работает

1. Cron раз в минуту запускает `yii mail/fetch-all` — команда обходит все активные
   почтовые каналы и забирает новые письма по IMAP.
2. Письмо, не относящееся к существующей заявке, создаёт новую заявку:
   тема письма → тема заявки, текст → описание, отправитель → автор обращения.
   Организация, категория, статус, специалист и приоритет берутся из настроек канала.
3. Ответ заявителя попадает в ту же заявку — как сообщение от заявителя,
   при необходимости заявка возвращается в статус «переоткрыта».
4. Специалист в карточке заявки выбирает тип сообщения:
   «Внутренняя заметка» остаётся в портале, «Ответ заявителю (email)» ставится
   в очередь на отправку.
5. Cron раз в минуту запускает `yii mail/send-pending` — очередь ответов уходит
   заявителям по SMTP, до 5 попыток при сбое.

## Сопоставление письма с заявкой

Приоритет проверок:

1. Заголовок `In-Reply-To`.
2. Заголовок `References`.
3. Номер заявки в теме письма, например `[tkt#000184] Re: Не работает вход`.

Если совпадений нет, создаётся новая заявка.

## Настройка

### 1. Ключ шифрования

Пароли IMAP/SMTP хранятся в базе в зашифрованном виде. В `.env` добавьте:

```
APP_SECRET_KEY=<результат php -r "echo bin2hex(random_bytes(32)), PHP_EOL;">
```

Если ключ не задан, используется `COOKIE_VALIDATION_KEY`. При смене ключа
пароли ящиков нужно ввести заново.

### 2. Расширение PHP imap

В `Dockerfile` расширение уже подключено. Пересоберите образ:

```bash
docker compose build php && docker compose up -d
```

Проверить: `php -m | grep imap`.

### 3. Миграции

```bash
php yii migrate
```

Будут созданы таблицы `mailboxes` и `email_messages`,
а также добавлены поля `tickets.mailbox_id`, `ticket_replies.is_public`,
`ticket_replies.email_status`, `ticket_replies.email_sent_at`.

### 4. Подключение ящиков

Раздел «Почтовые каналы» в меню администратора: «Подключить ящик» →
параметры IMAP/SMTP и правила маршрутизации → «Проверить подключение» →
«Забрать письма сейчас» для проверки без ожидания cron.

Пример нескольких каналов:

| Ящик | Категория | Специалист | Результат |
|---|---|---|---|
| support@company.ru | Техническая поддержка | дежурный инженер | техническая заявка |
| billing@company.ru | Бухгалтерия | бухгалтер | финансовая заявка |
| sales@company.ru | Продажи | менеджер | коммерческое обращение |

### 5. Cron

```cron
* * * * * php /var/www/html/yii mail/fetch-all >> /var/log/hd-portal-mail.log 2>&1
* * * * * php /var/www/html/yii mail/send-pending >> /var/log/hd-portal-mail.log 2>&1
```

Команды для ручной проверки:

```bash
php yii mail/test 1        # проверка подключения к каналу с id=1
php yii mail/fetch 1       # разовый приём писем одного канала
php yii mail/send-pending  # отправка накопившейся очереди
```

## Защита от типичных проблем

- Дубли писем исключены уникальным индексом `(mailbox_id, message_id)`.
- Письмо помечается прочитанным только после успешного сохранения заявки в БД.
- Автоответы и рассылки (`Auto-Submitted`, `Precedence: bulk/list/junk`,
  `List-Unsubscribe`) пропускаются, письма с собственного адреса игнорируются —
  так исключаются почтовые петли.
- Внутренние заметки никогда не отправляются заявителю: по умолчанию новая
  запись обсуждения — именно заметка.
- HTML входящих писем сохраняется в журнале, но в заявке отображается только
  текстовая версия — это исключает XSS через письмо.

## Что осталось за рамками первой версии

- Вложения писем: имена файлов добавляются в текст сообщения, но сами файлы не
  сохраняются — в проекте пока нет файлового хранилища. Это отдельная задача:
  потребуется таблица `email_attachments` и хранилище файлов с проверкой
  размера и типов.
- Перенос приёма и отправки в очередь (`yii2-queue`) при росте потока писем.
- Автоответ заявителю о регистрации обращения.
