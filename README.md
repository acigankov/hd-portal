# Hd-portal 

- Разработка в ветке dev 

# Установка

- Склонирвоать проект ``git clone``
- Скопировать ``.env.example`` в ``.env`` и заполнить значения
- Сгенерировать ключ подписи cookie и положить его в ``COOKIE_VALIDATION_KEY``:
  ``php -r "echo bin2hex(random_bytes(16)), PHP_EOL;"``
- Сделать ``composer``
- Сделать миграции ``php yii migrate``
- Сделать миграции RBAC ``php yii migrate/up --migrationPath=@yii/rbac/migrations``
- Добавить пользователя 
- Добавить роль

# Окружение и режим отладки

``YII_DEBUG`` и ``YII_ENV`` задаются только через ``.env``, в коде их менять не нужно.
Если переменных нет, приложение считает окружение производственным
(``YII_ENV=prod``, отладка выключена).

Для локальной разработки:

```
YII_ENV=dev
YII_DEBUG=true
DEV_TOOLS_ALLOWED_IPS=127.0.0.1,::1
```

Debug-панель и Gii поднимаются только при ``YII_ENV=dev`` и только для IP из
``DEV_TOOLS_ALLOWED_IPS``. Gii умеет создавать файлы на сервере, поэтому
указывать в этом списке ``*`` нельзя.

# Учётные данные

- Пароли не хранятся в репозитории. Файл ``users_credentials.txt`` больше не
  отслеживается git и добавлен в ``.gitignore``.
- Сид-миграция ``m260901_130000_seed_users_data`` генерирует случайные пароли и
  печатает их один раз при выполнении ``php yii migrate``. Для локальной
  разработки можно задать единый пароль через ``SEED_DEFAULT_PASSWORD`` в ``.env``.
- Пароли, которые ранее лежали в репозитории, считаются скомпрометированными —
  их нужно сменить у всех учётных записей.

# Права доступа

- Приложение целиком закрыто фильтром в ``config/web.php``: гостю доступны
  только ``login``, ``signup``, ``request-password-reset`` и ``error``.
- Модуль ``rbac`` (пользователи, роли, права, назначения, маршруты) доступен
  только пользователям с ролью ``admin``.
- Пользователи со статусом ``0`` (неактивные) не могут войти в систему.
